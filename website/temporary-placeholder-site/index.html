What We Are Building Now

Fixing the language, shipping examples, building the tools that prove the pitch

VG is a public beta. The thesis is proven by the AI correctness benchmarks above. What comes next is making the product reliable and demonstrable enough to hand to someone during the AI trust collapse and say: this is how you write code you can actually read.

Fix the four known bugs Boolean Or runtime regression, unhandled errors corrupting app state, phantom button double-press on async calls, and double-click ignoring existing .tscn signal connections. These must be solid before any public push.
20 proven working examples Every example in the repo must compile and run correctly. Currently the corpus has unproven files. The cleanup pass produces 20 examples that work, period — the proof points that make VG credible to a newcomer.
UI Forms — WYSIWYG in Godot's 2D viewport A new lightweight form editor that works with Godot's 2D editor, not against it. Floating control picker window, ghost placement, single click to place, double-click to auto-wire and generate a VG event stub. Replaces the current Form Designer, which has known bugs. Ships as an experimental plugin.
Code Navigator upgrade Extend the existing VB6-style Object/Event dropdown bar to surface every script attached to any node in the open scene. Select a node, the right dropdown fills with its procedures — VG Sub or GDScript func. No hunting through the scene tree to open a child node's script.
Narcea AI pair — generate VG from plain English Describe what you want. Narcea writes the VG code. You can read every line of it. This is the 60-second demo that makes the positioning real: AI writes it, you understand it, you trust it.
AI Transport Compaction Reversible codec that reduces AI prompt and response token usage 15–60% at the provider boundary. Source files are never changed. Pays for itself immediately in API costs.

Why BASIC-Like Syntax

VB6 readability, re-aimed at AI-assisted programming

Readable control flow beats punctuation-heavy code

In Visual Gasic, blocks end with explicit markers like End If and End Sub. That is old-school on purpose. It gives the language the same immediate legibility that made classic BASIC approachable, while also giving modern LLMs fewer ways to silently mis-nest logic behind braces, templates, callbacks, and symbolic clutter.

Auditing AI output should feel like proofreading, not archaeology

C++ is powerful, but power is not the same thing as inspectability. The practical question in the AI era is what a human can verify fast after the model emits its first draft. BASIC-style code narrows the audit surface: fewer symbolic traps, fewer ownership hazards, less build-system noise, and less chance that one tiny character hides a real bug.

Keep the runtime fast, keep the application code legible

Visual Gasic is not pretending that everything should be rewritten in BASIC. The compiler, runtime, and engine integration stay in C++ where that makes sense. The code humans and AI need to read, fix, and extend lives in a language designed for that job.

The AI benchmark result is the whole thesis in numbers

In the published AI correctness benchmark, Claude Sonnet 4.5 hit 25/25 parse-success on Visual Gasic, and local qwen2.5-coder:7b also hit 25/25 on Visual Gasic while dropping to 17/25 on GDScript and 21/25 on TypeScript. That is exactly the kind of first-draft reliability this language is meant to optimize for. Coding for the masses only matters if the machine can write it and the human can still trust it.
